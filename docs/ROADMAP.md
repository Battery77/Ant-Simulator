# 구현 로드맵

각 단계는 독립적으로 테스트 가능하며, 완료 조건을 모두 만족해야 다음 단계로 넘어간다.
개미·여왕개미는 7단계 이후에 다룬다.

## 1단계 — 코어 프로젝트와 월드 데이터 모델 ✅

- 솔루션 구조, Godot 비의존 `AntSim.Core`, xUnit 테스트, 벤치마크 도구
- `WorldConfig`, `World`(2 레이어), `WorldLayer`, `Chunk`(SoA 타일·블록), `TypeRegistry`, 더티 추적, 결정적 콘텐츠 해시

완료 조건 (모두 `dotnet test`로 검증):
- [x] 잘못된 설정(크기 0/음수, 청크 크기 비정상, 상한 초과) 거부
- [x] 청크 배수가 아닌 크기(1000×1000) 지원, 가장자리 청크의 유효 영역 정확
- [x] 청크 경계를 가로지르는 Set/Get 왕복 일치, 범위 밖·미등록 ID 거부
- [x] 두 레이어, 타일/블록이 서로 독립
- [x] 실제로 값이 바뀐 청크만 더티 표시, 수집 시 행 우선 순서, 수집 후 초기화
- [x] 같은 편집 → 같은 해시, 청크 크기와 무관한 해시, 해시 값 고정 테스트
- [x] 1024×1024 기준 성능 측정값 기록 (`BENCHMARKS.md`)

## 2단계 — 편집 연산 (Q1, Q18, Q19 확정 필요)

- 브러시(점·사각형·원·선), 청크 단위 span 대량 쓰기, 편집 명령 + Undo/Redo
- 완료 조건: 브러시별 칸 집합 정확성 테스트, Undo→Redo 후 해시 원복, 대량 채우기가 칸 단위 `SetTile` 대비 빠름(측정)

## 3단계 — 냄새 필드 기반 (Q7~Q12, Q16 확정 필요)

- 종류별 연속 배열 `ScentField`, 냄새 레지스트리, 확산·감쇠 기준(스칼라) 구현
- 완료 조건: 감쇠 없고 닫힌 경계일 때 총량 보존, 대칭 확산, 안정 조건 위반 설정 거부, 같은 입력 → 비트 단위 같은 결과, 1024² 기준 틱당 비용 측정

## 4단계 — 고정 틱 시뮬레이션 실행기 (Q14, Q15, Q17)

- `SimulationRunner`(누적 시간 → 고정 dt 틱), `ISimulationSystem` 파이프라인, 결정적 PRNG, 틱 경계 명령 큐
- 완료 조건: 프레임 delta를 어떻게 쪼개 넣어도 같은 틱 수·같은 해시, 시드 같으면 같은 결과

## 5단계 — 저장/불러오기

- 버전이 있는 바이너리 맵 형식(레지스트리 키 포함 → ID 재매핑)
- 완료 조건: 저장→불러오기 해시 일치, 구버전/손상 파일 거부

## 6단계 — Godot 프론트엔드

- 청크별 텍스처 렌더링, 카메라(줌/이동), 레이어 전환, 편집 UI, 냄새 오버레이
- 완료 조건: 1024² 맵 편집 시 더티 청크만 업로드, 목표 프레임레이트 측정

## 7단계 — 측정 기반 최적화

- 냄새 활성 청크, SIMD, 병렬화 — 3단계 기준선 대비 개선을 수치로 확인, 결정성 테스트 유지
