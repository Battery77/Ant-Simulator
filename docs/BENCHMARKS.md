# 기준 성능 측정

실행: `dotnet run -c Release --project tools/AntSim.Benchmarks [-- <size> <iterations>]`
환경: Intel Xeon 2.10GHz (클라우드 VM), 4 논리 코어, .NET 8.0, Release, 1024×1024, 청크 64, 7회 중앙값.
VM이라 같은 항목도 실행마다 최대 2~3배 흔들릴 수 있다(예: 월드 생성 4.8~37ms). 비교는 같은 환경에서 연속 실행한 값으로 한다.

## Phase 1 — 월드 데이터 + 편집기 (2026-10-29)

| 항목 | 시간 | 요소당 |
|---|---:|---:|
| World 생성 (2 레이어, 8MB) | 4.8 ms | 2.3 ns/타일 |
| `TrySetState` 전체 순회 (검증 + 4평면 쓰기) | 22.9 ms | 21.8 ns |
| `GetState` 전체 순회 | 7.2 ms | 6.9 ns |
| `CopyRow` 전체 (1 평면) | 0.68 ms | 0.64 ns |
| `MapEditor.Apply` 단일 연산 100k회 + 전체 Undo | 222 ms | 1.1 µs/연산 |
| 드래그 스트로크 (51k칸, Undo 1단계) | 30.8 ms | 0.6 µs/칸 |
| `CollectDirtyChunks` (256 청크) | 0.003 ms | 12.5 ns/청크 |
| `ChunkRasterizer` 레이어 전체 (256 청크) | 11.3 ms | 10.8 ns/타일 |
| `MapSerializer.Save` (8.0 MiB) | 13.7 ms | 6.5 ns/타일 |
| `MapSerializer.Load` (검증 포함) | 26.3 ms | 12.6 ns/타일 |
| `ComputeContentHash` | 14.9 ms | 7.1 ns/타일 |

해석
- 편집 명령은 연산당 약 1µs(검증·Undo 기록 포함). 드래그 한 프레임에 수십~수백 칸이므로 프레임 예산(16ms)에 비해 충분히 작다.
- 레이어 전체 다시 그리기는 약 11ms. 평소에는 더티 청크(64²당 약 44µs)만 다시 그리므로 문제 없다. 새 맵·불러오기 때만 전체 비용이 든다.
- 저장 파일은 압축 없이 8MiB. 크기가 문제가 되면 형식 v2에서 압축을 추가한다(버전 필드로 구분).

## 복합 히트맵 (2026-10-29)

1024×1024 한 레이어, Release, 같은 VM. 두 번 이상 실행해 확인한 대표값.

| 항목 | 시간 | 비고 |
|---|---:|---|
| 단일 히트맵, 선형 | 3.2~3.7 ms | 기존과 같은 수준(SIMD 양자화 공용화 후) |
| 단일 히트맵, 로그 | 4.6~9 ms | 칸마다 log 1회 |
| **복합(음식+유충), 선형** | **6.8 ms** | 첫 구현 14.3 ms → 조회표·2채널 전용 경로·SIMD 양자화로 개선 |
| 복합(음식+유충), 로그 | 13.5 ms | 칸마다 log 최대 2회 |
| 냄새 1틱 (2종 × 2레이어) | 16~20 ms | 변경 없음(냄새 계산 코드 미변경, VM 편차 범위) |

- 히트맵 래스터는 메인 스레드에서 새 스냅샷이 올 때만 실행된다. 계산 스레드의 추가 비용은 필드 복사(종류당 약 1ms)뿐이며,
  재생 중 게시를 30Hz로 제한하고 히트맵을 끄면 복사 자체를 하지 않는다.
- 시도했다가 버린 것: `float→uint` SIMD 변환·축소는 x86에서 소프트웨어 처리되어 오히려 3배 느렸다(→ `int` 경로 사용).
- Godot Debug 빌드 실측(가상 디스플레이): 복합 히트맵 42.9 ms(첫 구현) → 13.4 ms.

## 3차 — 냄새·시뮬레이션 (2026-10-29)

같은 환경, 1024×1024, 개미집 프리셋 + 통로 굴착 2,000회 + 먹이 설정 5,000회, 기본 냄새 설정(2종).
(감사 후 실측 입력 통계: 좌표가 겹쳐 실제로는 고유 통로 1,020개, 먹이 발생원 1,024칸, 유충 발생원 0칸,
개미집 열린 칸 0.88%. 아래 "감사 수정" 절 참고.)

| 항목 | 시간 | 요소당 |
|---|---:|---:|
| 냄새 1틱 (2종 × 2레이어 = 420만 칸) | 16.2 ms | 3.9 ns/칸 |
| → 0.1초 틱 실시간(×1) 재생 시 계산 부하 | 약 16% | |
| 히트맵 래스터 (레이어 1장, 선형, LUT) | 2.2 ms | 2.1 ns/칸 |
| 히트맵 래스터 (개선 전, 칸마다 색 계산) | 17.3 ms | 16.5 ns/칸 |
| `World.Clone` (시뮬레이션 시작) | 2.2 ms | |
| 통로 생성 1,000회 (굴착 + Undo 기록) | 3.7 ms | 3.7 µs/회 |
| 실험 파일 저장 (32 MiB) | 109 ms | |

해석
- 단일 스레드 냄새 계산으로 ×5 속도까지 실시간 재생이 가능한 수준이다. 더 빠른 재생이나 냄새 종류 증가에는 활성 청크 건너뛰기, 행 묶음 병렬화(Next 버퍼만 쓰므로 결정성 유지 가능), SIMD를 측정 후 검토한다.
- 히트맵은 메인 스레드에서 돌므로 색 조회표로 바꿨다(8배 개선).
- 실험 파일은 냄새 필드(float)와 월드 두 벌을 압축 없이 담아 크다. 크기가 문제가 되면 실험 형식 v2에서 압축한다.

## 감사 수정 전후 (PR #2 독립 감사, 2026-10-29)

환경: Linux x86-64 컨테이너 4코어, .NET 8.0.132, Release, `tools/AntSim.Benchmarks`.
수정 전 바이너리(cc5d416)와 수정 후 바이너리를 번갈아 8회씩 실행(Godot 등 다른 부하 없음). 단위 ms, 중앙값(최소~최대).

측정 입력(벤치마크가 직접 출력): 고유 통로 1,020개, Surface 열린 칸 100%·먹이 발생원 1,024칸·유충 0칸,
Nest 열린 칸 9,180/1,048,576(0.8755%). **실제 게임 맵을 대표하지 않는다**(개미집 대부분이 고체라 확산 비용이 작고, 유충 냄새는 발생원이 없다).

| 항목 | 수정 전 | 수정 후 | 판단 |
|---|---:|---:|---|
| 냄새 1틱 (2종 × 2레이어) | 20.4 (17.1~32.0) | 20.1 (17.7~35.4) | 차이 없음(잡음 범위) |
| 히트맵 래스터 선형 | 4.3 (3.5~6.2) | 3.8 (3.6~7.7) | 차이 없음(선형 경로 코드 동일) |
| 히트맵 래스터 로그 | 10.0 (7.9~15.1) | 11.1 (6.3~12.3) | 약 +10%로 보이나 분산이 커 유의하다고 보기 어려움(log1p를 double로 계산) |
| 복합 래스터 선형 | 7.8 (6.9~12.4) | 7.1 (6.9~14.5) | 차이 없음 |
| 복합 래스터 로그 | 17.8 (13.0~22.3) | 16.3 (15.5~27.6) | 차이 없음(잡음 범위) |
| 실험 파일 저장 (32 MiB) | 106.8 (98.3~109.5) | 112.6 (100.2~115.7) | 약 +5%: 저장 전 농도 범위 검사(전체 순회) 추가 |
| 맵 불러오기 | 33.3 (29.4~38.4) | 30.5 (29.0~37.7) | 차이 없음 |

- 컨테이너 공유 CPU라 같은 바이너리도 실행마다 최대 2배까지 흔들린다. 한 자릿수 % 차이는 이 측정으로 구분할 수 없다.
