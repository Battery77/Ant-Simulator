# 냄새 성능 기반 설계안 — 지상 묶음 격자 + 개미집 열린 칸 전용 계산

> 상태: **승인(2026-11-16, P-1~P-6 모두 제안대로), 구현 중**. 기준 코드: `main` @ `c968c01`(PR #4 병합 후).
> 구현: `ScentGrid`(배치), `ScentState`(배치별 저장·값 이동), `ScentSystem`(묶음 격자·압축 확산, 바뀐 레이어만 배치·발생원 갱신),
> 감각·스냅샷·히트맵(지상 선형 필터 확대)·`.antexp v4`(v1~v3 변환). 측정 결과는 BENCHMARKS.md에 기록한다.
> 방향(사용자 결정, 2026-11-16): 과학 실험형이 아니라 게임형. 계산은 단순하게, 성능과 디테일에 집중.
> 개미 수는 유지하거나 줄이고, 지도·자원 종류·다른 생물을 늘리는 것이 목표다.
> 이름 앞에 **(제안)**이 붙은 타입·필드·메서드는 아직 없다.

## 1. 왜 냄새부터인가

- 세션 한 틱의 가장 큰 비용은 냄새 확산이다. 1024² × 2레이어 × 2종에서 냄새 1틱이 약 14~20 ms(BENCHMARKS.md, 여러 회 측정)이고,
  10만 마리 세션 1틱 약 30 ms 중 절반 이상이다.
- 비용은 **지도 면적 × 레이어 × 냄새 종류**에 비례한다. 지도를 2048²로 넓히고 종류를 4개로 늘리면 약 8배가 된다.
- 현재 구조(`ScentSystem`):
  - 확산(`Diffuse`)과 감쇠·발생(`DecayAndEmit`)이 레이어마다 지도 전체 W×H를 매 틱 돈다. 고체 칸은 건너뛰지만 순회는 한다.
  - 개미집은 대부분 흙이다. 벤치마크 지도에서 열린 칸은 0.88%뿐이라, 개미집 계산의 대부분이 고체 칸을 건너뛰는 데 쓰인다.

## 3. 지상: 묶음 격자 (P-1, P-4)

- 지상 냄새 배열 크기: ⌈W/F⌉ × ⌈H/F⌉ (F = 4, 1024²이면 256²).
- **열린 묶음 칸**: 안의 F×F 칸 중 하나라도 고체가 아니면 열림. 이웃 묶음 칸끼리는 둘 다 열려 있을 때만 교환한다.
  - 대가: 지상의 얇은 바위벽(1~3칸)은 냄새를 막지 못할 수 있다. 지상은 넓게 트인 땅이라 받아들인다.
- **발생**: 묶음 칸 안 F×F 칸의 먹이·유충 수량 합 × e × dt / F². 칸 하나의 평균 농도로 다뤄 지금과 같은 크기 단위를 유지한다.
- **확산 계수**: 묶음 칸 사이 교환율 a' = D·dt / F². 칸 간격이 F배라 같은 시간에 같은 거리만큼 퍼지게 한다(확산 방정식의 격자 크기 보정).
  - 안정 조건 (4·D/F² + Dp)·dt ≤ 1이 지금보다 느슨해진다.
- **감쇠**: 그대로 exp(−k·dt).
- 냄새 종류 구성·계수 설정(UI의 D, Dp, k, e)은 그대로 두고, 내부에서 보정한다.

## 4. 개미집: 열린 칸 전용 계산 (P-2, P-3)

- 개미집 냄새 값은 열린 칸만 **압축 배열**(행 우선 순서)로 저장한다. 길이 = 열린 칸 수.
- 열린 칸마다 이웃 4개의 압축 인덱스(없거나 고체면 −1)를 미리 만들어 둔다. 확산은 압축 배열만 돈다.
  - 계산량 = 열린 칸 수 × 종류 수. 지도 크기와 무관하다.
- 칸 → 압축 인덱스 조회: 청크(64²)별 표를 **열린 칸이 있는 청크에만** 만든다. 2048²나 4096² 지도에서도 판 영역만큼만 메모리를 쓴다.
- 땅이 바뀌면(편집·나중에 개미가 파기) 바뀐 청크가 있을 때만 목록을 다시 만들고 기존 값을 옮긴다.
  - 새로 열린 칸은 0, 막힌 칸의 값은 버린다. 지금의 "고체 칸 농도 = 0" 규칙과 같다.
  - 지금도 `RefreshCaches`가 청크 버전으로 바뀐 청크만 다시 읽으므로 같은 신호를 쓴다.
- 방 사이 벽이 1칸이어도 정확히 막힌다. 방·복도 구분이 필요 없다.

## 5. 두 레이어 연결과 다른 시스템

| 대상 | 변경 |
|---|---|
| 통로 교환 | 통로 칸의 "지상 묶음 칸 ↔ 개미집 칸"끼리 교환. 묶음 칸 쪽 변화량은 1/F²로 나눠 총량을 보존 |
| 감각(B1) | 지상: 센서 칸이 속한 묶음 칸 값. 개미집: 압축 인덱스로 조회. 벽 판정은 지금처럼 원래 해상도의 고체 여부 |
| 스냅샷·히트맵 | 지상은 묶음 격자를 그대로 복사하고 화면에서 확대(GPU 텍스처 필터로 부드럽게). 개미집은 표시용 W×H 배열에 압축 값을 풀어 넣음 |
| 타일 정보(Inspector) | 그 칸이 속한 묶음 칸 값 또는 압축 값 |
| 개미 이동 | 변경 없음(속도는 냄새가 아니라 타일 수량을 본다) |

## 6. 저장 (P-5)

- `.antexp v4`: 냄새 구간만 바뀐다. 지상은 묶음 격자 배열, 개미집은 열린 칸 수 + 압축 배열(행 우선). 그 밖은 v3와 같다.
- v1~v3 불러오기: 지상은 묶음 칸 평균, 개미집은 열린 칸 값만 골라 변환한다. 결정적이며, 저장은 항상 v4.
- 기존 방어(할당 전 길이 확인, 체크섬, 연속 레코드)는 유지한다. 개미집 열린 칸 수는 내장 월드에서 다시 세어 파일 값과 맞는지 확인한다.

## 7. 테스트·측정

- **Stage A 이동 골든**(움직임·이동 난수 해시)은 그대로여야 한다.
  냄새·월드·틱을 묶은 세션 해시(`session.300` 등)와 냄새 골든은 의도적으로 바뀌므로 새로 고정한다(P-6). 바뀌는 값 목록을 PR에 적는다.
- 새 테스트:
  - 묶음 격자의 총량 보존(감쇠 0)
  - 개미집 1칸 벽 양쪽의 냄새 분리
  - 땅 파기 뒤 압축 목록 재구성과 값 보존
  - 통로 교환 총량 보존
  - v1~v3 변환의 결정성
  - 반복 틱 할당 0
- 측정(같은 VM에서 변경 전후 교차 실행):
  - 냄새 1틱, 세션 1틱(개미 1만 / 10만)
  - 1024²와 2048² 지도, 냄새 2 / 4종
  - 개미집 판 칸 1천 / 1만 / 10만
- 예상(미측정): 지상은 약 1/16, 개미집은 판 칸 비율만큼으로 줄어 1024² 기준 냄새 1틱이 1~2 ms 수준.
  실제 값은 구현 후 측정으로 대체한다.

## 8. 범위 밖

- 냄새를 따라 움직이는 행동, 먹이 운반, 새 자원·생물(다음 단계).
- 지상 묶음 칸의 벽 정밀화(필요해지면 묶음 칸을 연결 성분별로 나누는 방식을 검토).
- 냄새 계산 병렬화(이번 구조는 종류·레이어별 독립이라 나중에 적용 가능).
