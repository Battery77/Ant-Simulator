# 구현 전에 결정해야 할 게임 규칙

아래 항목은 **아직 확정하지 않았다.** 코드는 이 규칙들을 하드코딩하지 않고, 확정되면 데이터(레지스트리/설정)로 넣을 수 있도록 설계한다.
결정이 나면 이 문서에 기록하고 해당 단계에서 반영한다.

## 월드 / 타일 / 블록

1. **타일과 블록의 의미** — 현재 가정: 타일 = 바닥 재질, 블록 = 칸을 점유하는 물체(벽, 돌, 먹이 등). 맞는가? 한 칸에 블록은 최대 1개인가?
2. **타일·블록 종류 목록** — 어떤 종류가 필요한가? (예: 흙, 모래, 돌, 물 / 벽, 먹이, 장애물)
3. **종류별 속성** — 통행 가능, 굴착 가능, 냄새 흡수/차단, 이동 비용 등 어떤 속성을 둘 것인가?
4. **두 레이어의 관계** — 지상과 개미집 좌표가 1:1로 대응하는가(같은 크기, 위아래 겹침)? 레이어 간 이동(입구)은 어떻게 정의하는가?
5. **개미집 레이어 초기 상태** — 전부 흙으로 채워진 상태에서 굴착하는가, 빈 공간인가?
6. **맵 크기** — 고정(예: 1024×1024)인가, 실험마다 설정 가능한가? 지상과 개미집 크기가 같아야 하는가?
7. **맵 가장자리** — 벽으로 취급, 경계 밖으로 냄새 유실, 또는 순환(토러스)?

## 냄새

8. **냄새 종류** — 몇 종류이며 무엇인가? (예: 귀환 경로, 먹이 경로, 경보, 여왕 페로몬)
9. **확산·감쇠 모델** — 종류별 확산 계수/감쇠율? 감쇠는 지수형(비율)인가 선형(고정량)인가?
10. **타일·블록의 영향** — 블록이 냄새 확산을 막는가? 타일 재질별로 확산/감쇠가 다른가?
11. **레이어 간 냄새 이동** — 입구를 통해 지상↔개미집으로 냄새가 넘어가는가?
12. **값 범위** — 상한(포화)이 있는가? 아주 작은 값은 0으로 잘라내는가(활성 영역 축소에 중요)?
13. **바람 등 방향성 이동** — 필요한가?

## 시간 / 재현성

14. **시간 단위** — 1틱은 실제 몇 초인가? 1칸은 실제 몇 mm인가? (확산 계수 단위 결정에 필요)
15. **틱 속도** — 기본 틱/초, 배속 범위?
16. **재현성 범위** — 같은 PC·같은 빌드에서만 재현이면 충분한가, 다른 OS/CPU 간에도 비트 단위로 같아야 하는가?
    (후자라면 냄새를 float 대신 고정소수점 정수로 계산해야 하며 성능·설계에 큰 영향이 있다.)
17. **편집과 실행의 관계** — 시뮬레이션 실행 중에도 맵을 편집할 수 있는가? 편집도 재현 로그에 포함하는가?

## 편집기

18. **브러시 종류** — 점, 사각형, 원, 선, 채우기(flood fill) 중 무엇이 필요한가?
19. **Undo 범위** — 이력 개수 상한? 시뮬레이션 진행도 되돌리는가, 편집만 되돌리는가?
20. **냄새 직접 편집** — 편집기에서 냄새를 칠하거나 지우는 기능이 필요한가?
