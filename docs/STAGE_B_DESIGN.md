# Stage B 설계안 — 페로몬 감각과 집 방향 기억

> 상태: **설계 확정본(구현 전)**. 기준 코드: `main` @ `80f28aa`(PR #3 병합 후).
> 이름 앞에 **(제안)**이 붙은 타입·필드·메서드는 아직 존재하지 않는다. 그 밖의 이름은 현재 코드에 있는 것이다.
> 사용자 확정 사항: 13개 결정(I.1)과 추가 승인(I.2), 감지 거리 1타일(상한 2)·좌우 45°(상한 90°)·주기 0.3초·σ = 0.14 기본값,
> 레이어별 기억 정책, Stage C·D 제외, SA04 임시 통로 정책 유지.
> 개정 3: 감지 거리 상한을 2타일로 확정하고 남은 추천 사항을 승인으로 정리했다(I.2).
> 개정 2: 외부 검토 A~F를 코드와 대조해 확인된 항목만 고쳤다(타이머 경계, 감지 키 기본값, 선택 세대,
> Box–Muller 입력, 귀환 벡터 상한, 최근접 샘플링 정의). 감지 거리·각도도 설정으로 연다(I-12 변경).

## 요약

- **페로몬 감각 (B1)**
  - 개미 이동 루프 앞에 별도 감각 패스를 둔다.
  - 개미별 카운트다운 타이머 + id 기반 위상으로 주기(기본 0.3초)를 분산한다. 감지 직후 타이머는 항상 (0, P]이다.
  - 차폐 처리를 한 이중선형 보간으로 냄새 종류별 3방향 농도를 읽는다.
  - 감각은 난수를 쓰지 않으므로 Stage A 이동 결과가 바뀌지 않는다.
- **집 방향 기억 (B2)**
  - 기존 이동 루프 끝에서, 충돌 처리 후 실제로 지상에서 이동한 양으로 귀환 벡터를 갱신한다.
  - 오차 분산은 이동 거리 L에 대해 σ²·L이며, Stage A와 분리된 전용 난수를 쓴다.
- **저장**: B1이 `.antexp v3` 레이아웃 전체를 정의한다(B2 필드는 초기값으로 저장). B1 병합 뒤 레이아웃을 바꾸면 v4로 올린다. v1/v2 파일은 결정적 초기값으로 불러오고, 원본은 덮어쓰지 않는다.
- **순서**: B0(Stage A 골든) → B1(감각) → 감사·Windows 확인 → B2(경로 적분) → 감사·Windows 확인.
- **가장 큰 위험**: 10만 마리 감각 패스의 메모리 지연. 추정 범위가 넓어(틱당 +1~20ms) B1 초기에 실측한다.

## A. 현재 코드 구조

### A.1 틱 처리 순서
`SimulationSession.Step`은 틱마다 다음 순서로 동작한다.

1. 틱 간격 검사(SA03 방어)
2. `ScentSystem.Tick`: 확산 → 감쇠 → 발생 → `ScentState.Swap`
3. `AntSystem.Tick(Ants, World, AntSettings, (float)dt)`
4. `Tick++`, `ElapsedSeconds += dt`

개미는 **이번 틱에 새로 계산된 냄새(Current)**를 읽는다. 요청된 순서(페로몬 갱신 → 개미 처리)와 일치한다.

### A.2 `AntSystem.Tick`의 개미 한 마리 처리
1. `prevX/prevY = x/y`
2. 방향 결정(이동 난수 소비)
3. 속도 배율 갱신(현재 칸 수량 기준)
4. `AntMovement.Sweep`으로 이동
5. 막히면 탈출 방향 선택(난수 소비)
6. 틱이 끝난 위치가 새 칸이고 통로 중심이면 확률적으로 레이어 전환(난수 소비). 전환하면 `prev = 현재 위치`

### A.3 기존 데이터
- **`AntPopulation`(SoA, 개미당 63B)**
  - 식별·상태: `_id`, `_caste`, `_layer`, `_mobility`
  - 위치·방향: `_x`, `_y`, `_prevX`, `_prevY`, `_heading`, `_targetHeading`
  - 속도·크기: `_baseSpeed`, `_speedFactor`, `_size`
  - 기타: `_turnTimer`, `_turnIntervalScale`, `_lastTile`, `_rng`
  - 배열 관리: `Grow`가 모든 배열을 함께 늘리고, `Clear`는 `Count`와 `NextId`를 0으로 만든다(초기화 뒤 id 재사용).
- **이동 난수**: `AntRandom.CreateState(seed, id)`로 개미별 xorshift64* 상태를 만든다. 생성 위치 난수는 스트림 `ulong.MaxValue`를 쓴다.
  - `AntRandom.NextFloat = (NextULong >> 40) · 2^-24` → 범위 **[0, 1)**, 정확히 0이 나올 수 있다.
- **냄새**
  - `ScentSettings.MaxTypes = 256`. 기본 종류는 `food`, `larva` 2개지만 `Types`는 임의 키로 바꿀 수 있다(food·larva가 없는 설정도 유효).
  - 농도는 `ScentState`의 종류×레이어별 `float[W·H]` 배열(내부 `CurrentArray`)에 있다.
  - 확산은 비고체 4이웃끼리만 교환한다.
  - 실행 중에는 냄새 종류 구성을 바꿀 수 없다(`TrySetSettings`가 거부).
- **틱 간격**: `ScentSettings.TickSeconds` ∈ (0, 10]. 실행 중 `TrySetSettings`로 바뀔 수 있다(개미 있으면 `AntSettings.SupportsTick`도 확인).
- **개미 설정 변경**: `AntSettings`는 불변 레코드이고 초기화(`Reset`/`ApplyAntSettings`)로만 바뀐다. UI는 초기 개체 수와 시드만 노출한다(`SimulationPanel`).
- **통과 판정이 둘로 나뉜다**
  - 냄새 확산의 열린 칸: `ScentSystem._open`(비공개, 레이어별 `byte[]`). 고체가 아니면 열린 칸이며, **물은 냄새에 열려 있다**.
  - 개미 통과: `AntMovement.IsPassable`. 고체와 **물을 모두 막는다**. 청크 기반 `GetState`로 조회하므로 `_open`보다 비싸다.
- **월드 크기**: 레이어당 최대 2^28칸(예: 16384²), 기본 1024².

### A.4 화면 연결
- 계산 스레드의 `Publish`가 `ScentSnapshot`을 채운다. 스냅샷에는 `ResetCount`와 `AntFrame`(개미 10개 필드 전체 복사)이 들어간다.
- UI(`Main.Simulation`)는 `_selectedAntId`와 `_selectedAntResetCount`를 함께 기억한다.
  - `UpdateAnts`는 스냅샷 세대가 다르면 선택을 지운다. `DescribeSelectedAnt`도 세대가 다르면 null.
  - `ResetHost`가 선택을 지운다.

### A.5 저장
- `ExperimentSerializer` v2 레이아웃: v1 본문 → 개미 설정(고정 64B + 속도 구간) → 개미 본문(개미당 63B) → 체크섬.
- 개미 설정의 float 12개 중 1개는 예약 슬롯(0)이다.
- 이미 갖춘 방어
  - 할당 전 길이 확인(`StreamLimits.Require`)
  - seek 불가 스트림의 레코드 경계 유지(`LookaheadStream`)
  - 개체 필드 검증 공용화(`ValidateAnts`)
  - 저장 전 검사(`ValidateForSave`)
  - 문자열 길이 상한(`ReadString`, 65536B)
  - 실패한 불러오기에서 기존 세션 보존(`LoadExperiment`가 `Load` 성공 뒤에만 `StartSimulation`)
- 빠른 저장(Ctrl+S) 대상: 현재 `ReadExperimentVersion(path) >= 2`인 파일. **B1에서 "현재 형식(v3)인 파일만"으로 바꾼다**(I-10, v2 원본 보존).

### A.6 Stage B 통합 지점
1. `Step` 안, 냄새 틱과 개미 이동 루프 사이: 감각 패스
2. `AntSystem` 루프 끝: 경로 적분(이동 전후 위치와 레이어가 모두 있는 곳)
3. `AntPopulation`: 새 SoA 배열
4. `AntSpawner`(생성 시 초기화)와 `SimulationSession.Reset`
5. `ExperimentSerializer`: v3
6. 호스트 `Publish`, UI Inspector, `AntView`

## B. 아키텍처

```
SimulationSession.Step (틱마다)
 ├─ ScentSystem.Tick                       ← 기존 그대로 (Current = 이번 틱 농도)
 ├─ (제안) AntSensing.Sense(...)           ← 별도 패스: 감지할 차례인 개미만   [B1]
 │      읽기: X, Y, Heading, Layer / 냄새 Current / 냄새 열린 칸
 │      쓰기: 감각 SoA만 (난수 사용 없음)
 └─ AntSystem.Tick (기존 루프)
        기존 1~6단계 그대로
        + (제안) 루프 끝: PathIntegration.Update(i, 이전·이후 위치, 이전·이후 레이어)   [B2]
              전용 Nav 난수만 사용
```

### 감각은 별도 패스, 경로 적분은 루프 안에 두는 이유
- **감각**
  - 이동 전에 감지하므로 틱 시작 시점의 위치·방향을 읽는다. 루프 안에서 이동 전에 감지하는 것과 결과가 같다.
  - 공유 상태를 쓰지 않고 난수도 쓰지 않는다. 그래서 나중에 `Parallel.For`로 병렬화해도 결정성이 유지된다. 감각이 메모리 지연의 주요 병목(F절)이라 이 여지가 중요하다.
  - 추가 순회 비용은 10만 마리 타이머 확인 정도(약 0.1ms, 추정)다.
- **경로 적분**
  - 이동 직후의 실제 이동량과 레이어 전환 정보가 필요하다.
  - 기존 루프 끝에서 계산하면 추가 순회가 없다.
- Stage A 알고리즘(방향 결정·이동·충돌·통로)은 바꾸지 않는다. 루프 끝에 호출 하나만 추가한다.

### 의존 관계
- 감각 → `ScentState`(읽기), `ScentSystem`의 열린 칸 캐시(읽기, (제안) internal 접근자 추가)
- 경로 적분 → `AntPopulation`(이동 결과), 전용 난수
- Stage C는 감각 캐시와 귀환 벡터를 **읽기만** 하게 된다. Stage B에서는 이동 결정에 쓰지 않는다.

## C. 데이터 구조 (모두 (제안))

### C.1 설정 (`AntSettings`에 추가)

| 필드 | 형 | 기본값 | 검증 (모든 float은 NaN·±∞ 거부: `!(x >= lo && x <= hi)` 꼴) |
|---|---|---|---|
| `SensePeriodSeconds` | float | 0.3 | 0 초과, 60 이하 |
| `SensorDistance` | float | 1 | 0 초과, 2 이하 |
| `SensorAngleDegrees` | float | 45 | 0 초과, 90 이하 |
| `SensedScentKeys` | IReadOnlyList\<string\>? | null(기본 규칙) | C.1.1 |
| `PathErrorSigma` | float | 0.14 | 0 이상, 10 이하 |

- 감지 거리·각도·주기·σ 모두 설정이다(I-12 확정). 기본값은 확정값 그대로다.
- 거리 상한 2(확정): 차폐 DDA의 칸 조회 수가 최대 2⌈d⌉ + 1(d = 2이면 5)로 묶인다. 각도 상한 90(확정): 좌우 센서가 개미 뒤쪽으로 가지 않는다.
- `MaxSensedTypes = 8`: 해석된 키 수 K는 0~8이다.
- 설정은 `AntSettings`처럼 초기화로만 바뀐다. 실행 중 값이 바뀌지 않으므로 감지 일정이 중간에 흔들리지 않는다.
- **UI 노출**: B1에서는 새 입력란을 만들지 않는다(승인, I.2-2). 현재 UI가 개미 설정 중 개체 수·시드만 노출하고, 나머지 설정은 코드 기본값과 실험 파일로 전달된다. 값은 v3에 저장되므로 저장·불러오기 결과는 UI 유무와 무관하다.

#### C.1.1 감지 키 해석 규칙
`AntSettings.Validate`는 냄새 설정을 모르므로 규칙을 두 단계로 나눈다.

1. **`AntSettings.Validate`(키 목록 자체)** — `SensedScentKeys`가 null이 아니면
   - 개수 ≤ `MaxSensedTypes`(8)
   - 각 키가 null·빈 문자열이 아님
   - 중복 없음(서수 비교)
2. **세션 해석(생성·`Reset`·`ApplyAntSettings`·불러오기)** — 현재 `ScentSettings`와 맞춰 "해석된 키 목록"과 종류 인덱스를 만든다.
   - null(기본 규칙): `["food", "larva"]` 중 **현재 냄새 설정에 있는 키만, 이 순서로**. 둘 다 없으면 K = 0(감각 패스는 아무것도 하지 않음). 사용자 정의 냄새 설정을 깨지 않는다.
   - 명시 목록: 모든 키가 냄새 설정에 있어야 한다. 없는 키가 하나라도 있으면 설정 오류로 거부하고 기존 세션을 유지한다(조용히 빼지 않음).
   - 명시적 빈 목록은 K = 0으로 허용한다.
- 감지 값 배열의 순서는 **해석된 키 목록 순서**다(냄새 종류 인덱스 순서가 아니다).
- 실행 중에는 냄새 종류 구성이 바뀌지 않으므로 해석 결과는 다음 초기화까지 유효하다.
- 저장은 해석된 키 목록을 쓴다(E절). 불러오면 그 목록이 명시 목록이 되므로 동작이 같다.

### C.2 `AntPopulation`에 추가할 SoA 배열
K = 해석된 감지 키 수(0~8).

| 배열 | 형 | 바이트 | 의미 | 단계 |
|---|---|---:|---|---|
| `_senseTimer` | float | 4 | 다음 감지까지 남은 시간(초). 매 틱 감각 패스 뒤 항상 (0, P] | B1 |
| `_senseTick` | long | 8 | 마지막 감지 틱. -1이면 아직 감지 전 | B1 |
| `_senseHeading` | float | 4 | 감지할 때의 방향 | B1 |
| `_senseFlags` | byte | 1 | 센서 3개의 차폐 비트(bit0~2) | B1 |
| `_senseValues` | float | 12K | 개미 단위 연속 배치 `[i·K·3 + k·3 + d]`, d = 0 왼쪽 / 1 정면 / 2 오른쪽 | B1 |
| `_homeX`, `_homeY` | float | 8 | 추정 귀환 벡터(개미 → 기준 출구) | B2 |
| `_homeFlags` | byte | 1 | bit0 = 유효 | B2 |
| `_navRng` | ulong | 8 | 경로 적분 오차 전용 난수 | B2 |
| `_debugExitX`, `_debugExitY` | float | 8 | 실제 기준 출구 좌표(디버그 전용) | B2 |

- 개미당 증가량: **42 + 12K 바이트**. 기본 K = 2이면 66B이고, 기존 63B와 합쳐 129B.
- B2 배열도 B1에서 만들고 초기값으로 유지한다(형식 정책 E.1 (a)). B1에서는 읽거나 갱신하지 않는다.
- `_senseValues`는 하나의 배열에 개미 단위로 연속 배치한다. `Grow` 로직을 유지하면서 K를 곱한 크기로 늘리면 되고, 개미 하나를 쓰거나 Inspector가 읽을 때 캐시 효율이 좋다.
- K는 초기화나 불러오기 때만 바뀌므로 그때 배열을 다시 만든다.
- `_debugExit*`는 내부 접근만 허용한다. Stage C AI 입력 구조(예: (제안) `AntPerception`)에는 넣지 않는다(I-11).

### C.3 초기값 (생성 `TrySpawnValidated`와 v1/v2 불러오기 공통)
- 감지: `senseTick = -1`, 값 0, 플래그 0, `senseTimer = Phase(id)`(D.3, 범위 (0, P])
- 귀환 기억: `homeValid = false`, `home = (0, 0)`, `debugExit = (0, 0)`. 지상 생성이든 개미집 생성이든 무효(확정 사항).
- Nav 난수: `navRng = CreateState(seed, NavStream(id))`, `NavStream(id) = (1UL << 62) + id`. 이동 스트림(id), 생성 위치 스트림(`ulong.MaxValue`)과 겹치지 않는다(id < 2^31).

### C.4 메모리 추정 (구조 계산, 측정값 아님)

| 개미 수 | K=2 (66B/마리) | K=8 (138B) | K=32 (426B) | K=256 (3,114B) |
|---:|---:|---:|---:|---:|
| 100 | 6.6KB | 13.8KB | 42.6KB | 311KB |
| 1,000 | 66KB | 138KB | 426KB | 3.1MB |
| 10,000 | 660KB | 1.38MB | 4.26MB | 31MB |
| 100,000 | 6.6MB | 13.8MB | 42.6MB | **311MB** |

- 상한을 8로 확정했으므로(I-2) 10만 마리 최대 13.8MB다. K = 32 / 256 열은 상한을 두지 않았을 때의 비교용이다.
- 복잡도: 메모리 O(N·K), 계산 O(N·K·dt/P) + O(N).

## D. 알고리즘

### D.1 센서 좌표
d = `SensorDistance`, θ = `SensorAngleDegrees`. cθ = cos θ, sθ = sin θ는 설정을 해석할 때(생성·초기화·불러오기) 한 번만 계산해 둔다. 방향 h에 대해 c = cos h, s = sin h는 개미당 한 번 계산한다.

```
정면:          (x + d·c,                y + d·s)
왼쪽  (h − θ): (x + d·(c·cθ + s·sθ),    y + d·(s·cθ − c·sθ))
오른쪽(h + θ): (x + d·(c·cθ − s·sθ),    y + d·(s·cθ + c·sθ))
```

화면 좌표는 y가 아래로 증가하므로 각도를 줄이는 쪽(h − θ)이 화면에서 개미의 왼쪽이다. 확정된 정의(Heading − 45° = 왼쪽)와 일치한다.
cθ·sθ는 저장하지 않고 저장된 θ에서 다시 계산하므로, 불러온 뒤 같은 런타임에서 같은 값이 나온다(결정성 수준은 Stage A의 sin/cos 사용과 같다).

### D.2 농도 샘플링과 차폐 (확정: ③ 차폐 인식 이중선형)
"벽 자체의 샘플값"과 "센서까지의 차폐"를 나눠서 처리한다. 열린 칸 = 맵 안이고 냄새에 열린 칸(고체가 아님). 물은 열린 칸이다(I-3).

**1단계: 센서까지의 차폐**
- 개미가 있는 칸에서 센서점까지의 선분을 격자 DDA로 확인한다. 칸 조회는 최대 2⌈d⌉ + 1번(기본 d = 1이면 3번, 상한 d = 2이면 5번).
- 모서리를 대각으로 지날 때는 이동과 같은 규칙(두 축 중 한 칸을 먼저 거침)을 쓴다.
- 센서점이 맵 밖이거나 선분이 고체 칸을 지나면: 그 센서 값 = 0(모든 종류), 차폐 비트 = 1.

**2단계: 차폐되지 않은 센서의 이중선형 보간**
- 칸 중심 기준으로 보간한다: u = sx − 0.5, v = sy − 0.5, x0 = ⌊u⌋, y0 = ⌊v⌋, fx = u − x0, fy = v − y0. 주변 2×2칸, 가중치는 (1−fx)(1−fy) 등.
- 2×2칸은 항상 센서 칸을 포함하고 센서 칸의 3×3 이웃 안에 있다. 그래서 거리 d와 무관하게 샘플은 센서 칸에서 한 칸 이내다.
- 쓸 수 있는 샘플은 다음 두 조건을 모두 만족하는 칸이다.
  - (a) 맵 안이고 열린 칸이다. 맵 밖 좌표는 인덱스를 계산하기 전에 제외한다.
  - (b) 센서 칸에서 "보인다": 센서 칸 자신, 열린 상하좌우 이웃, 또는 사이의 두 칸 중 하나 이상이 열린 대각 이웃.
- 쓸 수 있는 샘플의 가중치만 다시 합해 1로 만든다(재정규화). 센서 칸은 1단계를 통과했으므로 항상 쓸 수 있다. 다만 그 가중치 자체가 0일 수 있으므로(예: fx = fy = 1에 가까운 경계), 합이 0이면 센서 칸 값을 그대로 쓴다.
- 가중치는 센서마다 한 번 계산하고, K개 종류에 같은 가중치로 칸 4개를 읽는다.
- 개미가 있는 레이어의 배열에서만 읽고 다른 레이어와 섞지 않는다.

**방식 비교**

| 방식 | 장점 | 문제 |
|---|---|---|
| ① 막힌 칸을 0으로 포함 | 가장 단순 | 벽 근처 값이 아래로 치우침. 얇은 벽 뒤의 칸이 샘플에 들어갈 수 있음 |
| ② 열린 칸만 재정규화 | 치우침 없음 | 막힌 모서리 너머의 대각 칸이 2×2 안에 있으면 그 값을 섞음 |
| ③ 센서 경로 + 샘플 보임 검사 (**확정**) | 벽 너머 감지 없음, 치우침 없음 | 센서당 열린 칸 조회 약 (2⌈d⌉+1) + 4번 |
| 센서→샘플마다 광선 검사 | 가장 엄밀 | 조회가 4배로 늘어 과함 |

**구체 예 (F 검증)** — 레이어 하나, 좌표는 타일 단위.
- 예 1 (개미와 센서 사이 벽): x = 6 열이 모두 고체. 농도 c(5,5) = 0.4, c(7,5) = 0.9.
  - 개미 (5.5, 5.5), h = 0, d = 1 → 센서 (6.5, 5.5)는 고체 칸 (6,5) → 차폐, 값 0. 0.9는 읽지 않는다.
  - 같은 개미, d = 2 → 센서 (7.5, 5.5)의 칸 (7,5)는 열려 있지만 DDA가 (6,5)를 지나므로 차폐. 거리를 설정으로 열었으므로 이 경우가 필요하다.
- 예 2 (센서는 도달하지만 2×2 일부가 벽): 같은 벽, 개미 (4.9, 5.5), h = 0, d = 1 → 센서 (5.9, 5.5), u = 5.4, v = 5.0.
  - 샘플 (5,5) w = 0.6, (6,5) w = 0.4(고체 제외), (5,6)·(6,6) w = 0. 재정규화 결과 = c(5,5) = 0.4. ①이면 0.24로 치우친다. x = 7 열은 2×2에 들어올 수 없다.
- 예 3 (막힌 모서리 너머 대각 칸): 고체 (6,5)·(5,6), 열린 (6,6)에 c = 0.9, c(5,5) = 0.4. 개미 (5.2, 5.2), h = 45°, d = 1 → 센서 ≈ (5.907, 5.907), 칸 (5,5).
  - 가중치 (5,5) 0.36, (6,5) 0.24, (5,6) 0.24, (6,6) 0.16. (6,6)은 사이의 두 칸이 모두 고체라 보이지 않음 → ③ = 0.4. ②는 (0.36·0.4 + 0.16·0.9)/0.52 ≈ 0.554로 벽 너머 값을 섞는다.
  - 확산은 4이웃이라 (5,5)와 (6,6)은 직접 교환하지 않는다. 벽을 돌아 확산으로 (5,5)에 도달한 냄새는 c(5,5)에 이미 들어 있으므로 감지된다.
- 맵 경계: 센서점이 맵 밖이면 1단계에서 차폐. 센서는 안이고 2×2 일부가 맵 밖이면 (a)에서 제외(배열 범위 밖 접근 없음).

- 이중선형 보간은 볼록 결합이라 값이 지원 범위(0~1e30) 안에 머문다.
- **최근접 칸 샘플링**은 게임 설정이 아니다. 벤치마크·테스트에서 비용을 비교하는 내부 경로로만 둔다(`AntSettings`에 없고 저장하지 않으며 실행 중 바꿀 수 없음). 게임 동작은 항상 ③이다. 나중에 실제 설정으로 승격하면 v3 설정 블록에 들어가야 하므로 형식 정책(E.1)에 따라 v4가 된다.

### D.3 감지 스케줄 (확정: 개미별 카운트다운 + id 기반 위상)
```
h(id)     = (uint)(id · 2654435761u)                     // 결정적, 난수 미사용
Phase(id) = P · (h(id) + 1) / 2^32                        // (0, P], double로 계산 후 float
생성 시 senseTimer = Normalize(Phase(id))

매 틱 감각 패스 (dt = (float)TickSeconds):
  t = senseTimer − dt                                     // float 뺄셈 (Stage A turnTimer와 같은 방식)
  if t <= 0:
      감지; senseTick = 현재 틱(감각 패스 시점의 Tick); senseHeading = h
      k = ⌊−t / P⌋ + 1                                    // double. t = 0이면 k = 1
      t = t + k·P                                         // double로 계산 후 float
  senseTimer = Normalize(t)

Normalize(t) = (t > 0 && t <= P) ? t : P                  // float 반올림·NaN 방어
```

- **불변식**: 감각 패스가 끝나면 모든 개미의 `senseTimer` ∈ (0, P]. 다음 감지는 항상 미래(최소 1틱 뒤)다.
- **이전 식의 결함(외부 검토 A, 확인됨)**: `senseTimer += P · ceil(−senseTimer / P)`는 타이머가 정확히 0이 되면 k = 0이라 0에 머물고, 다음 틱에 다시 감지한다.
  - float32 모델로 확인: dt = 0.1, P = 0.3, 초기 타이머 0.1 → 첫 틱에 0이 되어 1틱 뒤 재감지. dt = 0.1, P = 0.25 → 간격 1틱이 반복적으로 나온다(새 식은 2·3틱 교대, 평균 2.5틱).
  - 초기 위상 Phase(0) = 0도 같은 문제를 만든다. 새 식은 위상 범위를 (0, P]로 옮겼다.

| 조건 | 동작 (dt, P는 float) |
|---|---|
| dt = 0.1, P = 0.3 | float에서 0.3 − 3·0.1 = 1.49e-8 > 0이라 타이머 P에서 출발하면 4번째 틱에 첫 감지(남은 값 −0.09999999 → 0.2). 이후 3틱마다 감지 |
| 타이머가 정확히 0 | k = 1 → 타이머 = P. 다음 감지는 P 뒤 |
| dt > P (예: dt = 10, P = 0.3) | 매 틱 한 번만 감지(밀린 감지를 몰아서 하지 않음). 타이머는 (0, P]로 복귀 |
| P가 dt의 정수배가 아님 (dt = 0.07) | 경계를 넘는 틱에 감지. 간격 4·5틱이 섞이고 평균은 P/dt |
| 초기 위상 | Phase(id) ∈ (0, P]. 첫 감지는 1틱 ~ 약 ⌈P/dt⌉틱 뒤(float 반올림으로 1틱 늦을 수 있음). 같은 id → 같은 위상 |
| Reset | id가 0부터 다시 매겨지므로 같은 위상 → 같은 결과 재현 |
| 개미 수 변경 | 개체마다 독립 위상이라 영향 없음 |
| 틱 간격 변경(실행 중) | 남은 시간을 새 dt로 빼므로 자연스럽게 따라감. 불변식 유지 |
| 저장·불러오기 | v3: 타이머 float을 비트 그대로 복원 → 이어서 실행한 결과가 같다. v1/v2: Phase(id) |
| 첫 감지 전 | `senseTick = -1`로 무효 표시 |

- **float 한계(기존과 같음)**: dt가 타이머의 float 한 단위의 절반보다 작으면(예: P = 0.3에서 dt < 약 1.5e-8초) 뺄셈이 타이머를 바꾸지 못해 감지가 멈춘다. Stage A `turnTimer`도 같은 성질이며 틱 간격이 그렇게 작은 실험은 다른 계산도 의미가 없다. 별도 처리하지 않고 문서에만 남긴다.
- 대안(경과 시간 위상 교차)은 채택하지 않았다(I-5).

### D.4 경로 적분 (B2, 기존 이동 루프 끝)
```
layerBefore = 루프 시작 때 레이어, (x0, y0) = prev 값, (x1, y1) = 최종 위치

if layerBefore == Nest && layer == Surface:        // 지하 → 지상
    home = (0, 0); homeValid = true; debugExit = (x1, y1)   // 이 틱의 이동은 지하에서 일어남 → 적분 안 함
elif layerBefore == Surface && layer == Nest:      // 지상 → 지하
    homeValid = false
elif layer == Surface && homeValid:
    dx = x1 − x0; dy = y1 − y0                     // 충돌 처리 뒤 실제 이동량
    if dx != 0 || dy != 0:
        L = sqrt(dx² + dy²)
        s = σ · sqrt(L)
        (n1, n2) = 표준정규 쌍(navRng)              // 이동이 없으면 난수를 쓰지 않음
        homeX += −dx + s · n1
        homeY += −dy + s · n2
        if !(|homeX| <= HomeBound && |homeY| <= HomeBound): homeValid = false; home = (0, 0)
```

- **오차 크기**: 틱마다 분산 σ²L, 서로 독립. 전체 분산은 σ²·(총 이동 거리)이므로, 틱을 잘게 나눠도 통계적 오차는 같다.
- **충돌**: 이동이 0이면 갱신하지 않는다. 일부만 이동했으면 실제 이동량만 적분한다.
- **다른 출구로 다시 지상에 나옴**: 지하 → 지상 분기로 초기화된다.
- **기준점**: 전환이 일어난 틱 끝의 실제 위치(통로 중심 칸 안의 연속 좌표). 개미집 중심이 아니다.
- **분포 (확정: Box–Muller)**
  - u1 = 1 − `NextFloat` ∈ [2^-24, 1], u2 = `NextFloat` ∈ [0, 1). `NextFloat`가 정확히 0을 낼 수 있으므로(A.3) u1에 그대로 쓰면 ln 0 = −∞가 된다(외부 검토 D, 확인됨).
  - r = √(−2 ln u1) ≤ √(48 ln 2) ≈ 5.77, n1 = r·cos 2πu2, n2 = r·sin 2πu2. 항상 유한하다.
  - 비용은 log, sqrt, sincos 각 1번. 개미당 한 번 이동에 난수 2번.
- **귀환 벡터 상한**: `HomeBound = 1e7` 타일(승인). 정상 실험에서는 닿지 않지만(지도 최대 16384칸, 오차 표준편차 0.14·√총거리), σ 상한 10과 긴 실행을 조합하면 이론상 넘을 수 있다. 넘으면 기억을 무효화해 값이 항상 유한하고 저장 검증을 통과하게 한다. 위치는 항상 유한하므로 dx, dy, L도 유한하다.
- **수치 정밀도**: 귀환 벡터는 float. 16384칸 지도에서 float 한 단위는 약 0.002타일이고, 반올림 오차 누적은 설계 오차(0.14√L)보다 훨씬 작다.
- **Stage A와 분리**: 이동 난수(`_rng`)를 건드리지 않으므로 Stage A 이동 결과는 비트 단위로 같다.

### D.5 레이어별 정책 대응 (확정 사항)

| 상황 | 처리 |
|---|---|
| 지하 → 지상 | 해당 출구를 새 기준점으로, `home = (0,0)`, 유효 |
| 지상 이동 | 실제 이동량으로 적분 + 오차 |
| 지상에서 정지·충돌로 이동 0 | 갱신 없음, 난수 소비 없음 |
| 지상 → 지하 | 무효화 |
| 지하 이동 | 적분 안 함 |
| 지상에서 최초 생성 | 무효 |
| 다른 출구로 다시 지상 진입 | 이전 기억 버리고 새 출구 기준으로 초기화 |
| 마지막 먹이 위치 | Stage B에서 기록하지 않음(먹이를 실제로 집는 Stage D 이후) |

### E.1 형식 버전 정책 (같은 버전 번호에 다른 레이아웃을 쓰지 않는다)

| 방식 | 장점 | 문제 |
|---|---|---|
| **(a) B1이 v3 전체 레이아웃 정의 (승인)** | 버전이 하나만 늘어남. B2는 레이아웃 변경 없이 값만 채움 | B1에서 B2 필드를 미리 정해야 함 |
| (b) v3 = B1만, v4 = B2 | 단계별로 깔끔 | 버전과 변환 코드가 하나 더 늘어남. B1 파일은 B2에서 귀환 기억 무효로 불러와야 함 |
| (c) 같은 v3 안에서 하위 버전 번호 | 변경 범위가 작아 보임 | 사실상 숨은 버전. 검증 분기가 늘고 "v3인데 해석이 다른" 파일이 생김 |
| (d) 태그·길이 확장 레코드 | 장기적으로 유연 | 현재 고정 레이아웃 + 체크섬 구조와 맞지 않아 이번 범위에 비해 큼 |

**규칙((a) 승인)**
- B1 PR이 아래 레이아웃 전체를 정의하고, B2 필드는 C.3 초기값(귀환 무효, (0,0), Nav 난수 시드 상태)으로 쓰고 같은 규칙으로 검증한다.
- B2는 같은 필드에 실제 값을 쓴다. 레이아웃, 필드 의미, 검증 범위를 바꾸지 않는다.
- B1 병합 뒤 레이아웃이나 필드 의미를 바꿔야 하면 v3를 재사용하지 않고 v4로 올린다.
- B1과 B2 사이에 만든 v3 파일을 B2에서 불러오면 귀환 기억은 무효이고 Nav 난수는 시드 상태다. 이는 B1에서 저장 당시의 실제 상태와 같으므로 이어서 실행한 결과가 일관된다.

### E.2 레이아웃
v2 본문 → (제안) Stage B 설정 블록 → 개미별 Stage B 배열 → 체크섬

- **설정 블록**
  - 감지 주기, 센서 거리, 센서 각도, σ(float 4개)
  - K(≤ 8)와 K개의 키 문자열(해석된 키 목록, 감지 값 배열 순서). 키 이름으로 저장해 냄새 종류 순서가 달라도 대응을 유지한다.
- **개미별 배열**: C.2 순서. 개미당 42 + 12K 바이트(K = 2이면 66B).

### E.3 불러오기 검증 순서
1. 설정 블록 고정 부분을 `Require`로 확인하고 읽는다. float 4개는 C.1 범위(NaN·±∞ 거부).
2. K를 읽고 **문자열을 읽기 전에** K ≤ 8을 확인한다.
3. 키 문자열을 기존 `ReadString` 상한으로 읽는다. 빈 키·중복 키 거부, 각 키가 같은 파일의 냄새 설정에 있어야 함.
4. `n·(42 + 12K) + 8`(체크섬) 바이트가 실제로 있는지 `Require`로 확인한 뒤에만 배열을 할당한다.
5. 개체 필드 검증(`ValidateAnts` 확장, 저장 전 검사와 같은 규칙)
   - 감지 값: 유한, 0 이상, 1e30 이하
   - 감지 타이머: 유한, **0 초과 P 이하**(D.3 불변식)
   - 감지 틱: -1 이상, 현재 틱 이하
   - 감지 방향: 유한, 절댓값 2π 이하
   - 귀환 벡터: 유한, 절댓값 `HomeBound` 이하. 무효이면 (0, 0)
   - 디버그 출구 좌표: 유효이면 맵 안, 무효이면 (0, 0)
   - 플래그의 정의되지 않은 비트는 0
   - Nav 난수 ≠ 0
6. 체크섬. 실패하면 예외 → 기존 세션 유지(현재 `LoadExperiment` 동작 그대로).

- **v1/v2 불러오기**: 감각과 귀환 기억은 C.3 초기값으로 결정적으로 만든다(지상 개미도 귀환 기억 무효). 감지 설정은 기본값, 감지 키는 기본 규칙(C.1.1). 저장은 항상 v3.
- **빠른 저장 대상**: B1에서 `LoadExperiment`의 규칙을 "현재 형식 버전(v3)인 파일만 Ctrl+S 대상"으로 바꾼다. v1·v2 파일을 불러오면 다른 이름으로 저장하게 해 원본을 보존한다(I-10).
- **유지하는 기존 방어**: `LookaheadStream` 레코드 경계, 실패한 불러오기에서 기존 세션 보존, 임시 파일 교체 저장.
- **대안 비교**
  - v2를 유지하고 Stage B 상태를 저장하지 않음 → 불러온 뒤 재개 결과가 달라진다.
  - 별도 부속 파일 → "레코드 하나" 원칙이 깨진다.

## F. 성능 분석 (모두 추정, 측정값 아님)

### F.1 계산 비용
비교 기준(이전 실측): Stage A 개미만 1틱, 10만 마리, Release ≈ 16~19ms(마리당 약 170ns).

- **감각**
  - 한 틱에 감지하는 개미 = N·dt/P(dt ≥ P이면 N). dt = 0.1, P = 0.3이면 약 1/3.
  - 감지 1회: 센서 3개 × (차폐 조회 2⌈d⌉+1번 + 보임 검사 + 가중치 계산 + 4K번 읽기). 기본값에서 순수 연산 약 50~100ns로 본다. 거리를 늘리면 차폐 조회가 선형으로 늘어난다.
  - **병목은 메모리 지연**: 개미가 흩어져 있으면 센서 3개가 2~3행에 걸치고, 종류마다 1MB(열린 칸) + 4MB(농도) 배열을 무작위로 읽어 캐시 미스가 4~12번(K = 2) 날 수 있다.
  - 10만 마리: +1~3ms(개미가 모여 있는 경우) ~ +10~20ms(흩어진 최악).
- **경로 적분**: 이동한 지상 개미마다 sqrt 2번, 난수 2번, Box–Muller 1번. 10만 마리 중 지상 30%(이전 측정 비율)면 +0.5~1.5ms.
- **추가 순회**(감각 패스 타이머 확인): 약 0.1ms.
- **할당**: 틱당 0이 목표. 키→인덱스 변환과 가중치는 지역 변수나 미리 만든 버퍼를 쓴다.
- **스냅샷**: `AntFrame`에 Stage B 배열을 넣지 않는다. 넣으면 10만 마리 기준 게시 1회에 2.4MB, 30Hz면 72MB/s를 복사한다. 대신 **선택한 개미 하나의 상세만** 복사한다(G절, 수십 바이트).

### F.2 완화책
1. 감지 주기 늘리기(설정)
2. 감각 패스 병렬화(난수 없음, 쓰기 위치가 개미별로 분리 → 결정적)
3. 최근접 칸 샘플링은 측정 비교용 내부 경로다(D.2). 게임 설정으로 승격하려면 별도 결정과 v4가 필요하다.

개미 배열을 공간 순서로 다시 정렬하는 방법은 순회 순서와 결정성이 바뀌므로 이번 범위에서 제외한다.

### F.3 벤치마크 계획
- **공통 조건**: 1024² 개미집 + 통로 2,000개, 기본 설정, Release, JIT 예열, 교차 실행 5회 이상, 중앙값과 범위 기록.
- **비교 대상**
  - (a) Stage A만 / (b) 감각만 / (c) 경로 적분만 / (d) 둘 다 — B1은 (a)(b), B2는 (c)(d)
  - 최근접 칸(내부 경로) vs 이중선형
  - K = 2 / 8, 센서 거리 1 / 2
  - 개미가 모인 분포 vs 지도 전체에 흩어진 분포
  - 개미 100 / 1천 / 1만 / 10만
- **지표**: 틱당 시간, 틱당 할당량(`GC.GetAllocatedBytesForCurrentThread`), 1만 마리 2,000틱 누적 할당, Stage A 이동 필드 해시 불변 여부.

## G. 관찰·Inspector

- **(제안) 호스트 API `SelectAnt(int id, long resetCount)` / `ClearAntSelection()`**: 히트맵 선택처럼 계산 스레드가 알아야 할 표시 선택으로 다룬다.
  - 호스트는 `resetCount`가 현재 세션 세대와 다르면 요청을 무시한다. 초기화하면 호스트 쪽 선택도 지운다. 초기화 뒤 늦게 도착한 요청이 재사용된 id의 다른 개미 상세를 복사하지 않게 하기 위함이다(외부 검토 C).
  - `Publish` 때 그 개미의 Stage B 상세(K×3 값과 키, 감지 틱·방향·플래그, 귀환 벡터·유효 여부, 디버그 출구 좌표)를 스냅샷 안의 고정 버퍼에 복사하고, 상세에 `ResetCount`와 `Id`를 함께 싣는다.
  - UI는 기존 규칙(스냅샷 세대 검사)에 더해 상세의 `ResetCount`·`Id`가 자기 선택과 같을 때만 표시한다.
- **Inspector 문구 예**
  - `음식 L 0.12 / F 0.40 / R 0.05 · 3틱 전 (방향 37°)`
  - `귀환: 유효 · 12.3타일 · 214°` (B2)
  - `디버그: 실제 출구 방향 차이 4.1° · 거리 오차 0.6타일` (B2)
- **시각화**(선택한 개미만, `AntView._Draw` 확장)
  - 센서 점 3개: 값에 따라 색, 차폐된 센서는 X 표시 (B1)
  - 추정 귀환 화살표 (B2)
  - 디버그용 실제 출구 화살표: 다른 색, 끌 수 있게 (B2)
- **디버그 값 분리**: 실제 출구 좌표는 UI·디버그 경로에서만 접근한다. AI 입력 구조에는 넣지 않는다(I-11).
- UI 작업은 CLAUDE.md 절차(빌드·테스트, Godot 실행, 변경 전후 캡처, 미검증 표시)를 따른다.
